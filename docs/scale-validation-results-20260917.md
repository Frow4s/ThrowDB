# Проверка 400 млн векторов — 17 сентября 2026

Создание коллекции, полная проверка целостности и **112 из 112 измерений чтения**
завершились успешно. Проверялись embedded API и read-only gRPC-сервер на одной
коллекции **400 000 000 × 1024 float16**. Payload — 819,2 GB / 762,939 GiB;
полный логический размер файлов — 852 467 211 776 байт. Данные записаны целиком,
без sparse-файлов.

## Среда и версия

- Linux 6.1.0-42-amd64, x86_64, Intel Xeon Gold 6338; cgroup: **10 CPU, 256 GiB RAM**.
- OverlayFS поверх RAID1 из двух SATA SSD Samsung MZ7L33T8. NVMe не использовался.
- Python 3.11.8; библиотека из коммита **`de6ce4e`** и установленного wheel
  `throwdb-0.1.0-cp311-cp311-linux_x86_64.whl`, включая его native gRPC-сервер.
- SHA256 wheel: `d0233c2dc3e2403cc92a7404aedb32a2cd5b0e06d2a6b5145220b8a5fcf17a72`.
- Клиент и сервер работали на одном хосте через loopback без TLS. Настройки
  reader задавались явно; автоматическая калибровка не запускалась.

## Целостность и выборочная проверка значений

Создание с `finish` и первоначальной проверкой заняло 29 мин 40 с. Последующая
полная проверка заняла 26 мин 50 с: CRC проверен для всего payload, ID-sidecars
и snapshots; структурная проверка проверила индекс и соответствие записей
ID-sidecars. Подтверждено наличие 400 000 000 строк, файлы за время проверки
не изменились.

**Полный CRC проверяет целостность относительно сохранённых checksum.**
Независимый NumPy oracle регенерировал и побитово сверил **11 526 уникальных
векторов**: случайную выборку, крайние ID и границы сегментов. Это не независимая
регенерация всех 400 млн строк. Данные синтетические: конечные float16,
детерминированный hash и ID-tag.

Benchmark занял 7 мин 41 с. Проверены pread, thread pool с 4 workers,
embedded io_uring и gRPC io_uring: по 28 cases на конфигурацию. Выполнено
619 264 запроса; после timing побитово проверены **14 635 776 возвращённых строк
с повторами** и 12 168 462 336 значений float16. Измеряемый corpus содержит
**478 434 уникальных ID**, около **0,1196%** коллекции. Его SHA256 совпал между
backend, числом клиентов и cold/warm. Этот счёт уникальных ID не включает
отдельную проверку целостности и входные correctness gates.

## Холодный payload: 8 клиентов, полная размерность

Оба пути используют io_uring: **2 workers, QD 32 total**. Batch — число векторов
в запросе; p99 относится к целому запросу. Пропускная способность округлена
до целых векторов/с.

| Batch | Embedded, векторов/с | gRPC, векторов/с | Embedded p99, мс | gRPC p99, мс |
| --- | --- | --- | --- | --- |
| 1 | 14 194 | 7 246 | 0,548 | 2,257 |
| 16 | 64 070 | 63 875 | 2,554 | 2,705 |
| 128 | 81 719 | 82 764 | 14,556 | 14,718 |
| 1024 | 81 318 | 80 857 | 104,327 | 116,943 |

В этом прогоне большой холодный batch через gRPC достигал скорости, близкой
к embedded io_uring. Это не универсальный выбор backend: например, pread
при cold batch 1 и 8 клиентах дал 36 308 векторов/с против 14 194 у io_uring.

## Границы результата

- Cold-advised — `POSIX_FADV_DONTNEED` только для payload коллекции. Индекс
  прогрет проверкой checksum при open; cache устройства не сбрасывался.
  Индекс занимает 25,016 GiB, RSS процесса данных после open — около 25–26 GiB.
- Warm повторяет тот же ограниченный corpus, а не читает всю коллекцию из RAM.
  Во всех 56 warm cases `read_bytes` процесса данных не увеличивался;
  в 56 cold cases он составлял около 2× полного возвращаемого payload,
  что согласуется с чтением страницы 4 KiB для строки 2 KiB.
- Для batch 1/16/128/1024 использовано 20 000 / 4 096 / 1 024 / 256 запросов
  на case. Некоторые warm cases короче секунды; p99 batch 1024 основан всего
  на 256 наблюдениях. Это один прогон без доверительных интервалов и длительного soak.
- Timing включает публичный API, allocation, scheduling и RPC; генерация
  данных и побитовая проверка результатов выполняются вне timing. Prefix 128
  пока читает полную строку 1024 и уменьшает только возвращаемый объём.
- Во время измерений не было приращения OOM/OOM-kill или CPU throttling.
  gRPC-сервер завершился штатно с exit 0. Внешняя сеть, мутации, обслуживание
  и восстановление после отказов этим прогоном не проверялись.
